## 0. 一句话结论

**这不是 UI 工程，是数据工程。** 竞品强在数据完整（每一跳倍率、每个天赋等级、武器被动、命座、套装），我们的引擎公式已经对了，缺的是喂给它的数据。UI 上我们已有一个竞品没有的东西——摊开的六乘区公式链——要保住它，并在旁边补上竞品那张「每一招打多少」的表。

## 1. 竞品拆解：damage.paimon.app 有什么

实地看过（2026-09-20），它分三个标签页。

### CHARACTER

- 角色、等级、**命座 C0–C6**、**三个天赋等级各自可调**（普攻/战技/爆发，1–15）
- 被动天赋展示（可展开）
- **属性表：基础值 / 加成 / 总计** 三列，覆盖 HP、攻击、防御、精通、充能、暴击率、暴击伤害
- **Basic Buffs**：七元素伤害加成 + 物理 + 治疗加成，同样三列
- **Unique Buffs**：普攻/重击/下落/战技/爆发/全伤害 各自的增伤
- **Elemental Reaction Buffs**：超载/燃烧/蒸发/融化等各自的反应加成
- 「EDIT MANUALLY」手动改任意属性

### EQUIPMENT

- 武器：**精炼 1–5**、基础攻击、副词条、**被动文本 + 层数选择器**（例：四风原典「每 4 秒 8% 元素伤害，最多 4 层」→ 给出 0/8/16/24/32% 让用户点）
- 圣遗物：五件套主词条 + 副词条，支持导入
- **ENEMY 子页**：敌人等级、**七元素各自的抗性**、抗性削减、防御削减，实时显示防御乘区（48.7%）
- **PARTY BUFFS 子页**：角色增益 / 圣遗物增益 / 武器增益 / 元素共鸣，各自可勾选

### DAMAGE

一张表，列是 **Non-CRIT / CRIT / Average**，行是**每一跳**：

```
1-Hit DMG        1934   5263   4200
2-Hit DMG        1672   4551   3632
3-Hit DMG        2409   6558   5234
Total DMG        6015  16373  13066
Charged Attack   5324  14491  11565
Plunge / Low / High Plunge
Jumpy Dumpty DMG ×3    7653  20830  16624
Mine DMG ×8            7031  19138  15273
Sparks 'n' Splash ×19 21708  59090  47156
```

还带持续时间、冷却、能量消耗，以及一个反应区块（超载 4933、碎冰 3844、烈绽放 5382、燃烧 448、蒸发 +15%、融化 +15%）。另有 **Diff Mode**（改动前后对比）和 **COMPARE** 页。

| 角色被动 A1/A4 | ✓ | ✗ | 数据 |

### 现有数据的形状（这是最大瓶颈）

```ts
// src/data/talents.ts —— 每个角色只有四个数字
'diluc': { normal: 8.107, charged: 3.825, skill: 2.318, skillLabel: "3-Hit DMG", burst: 3.672, burstLabel: "Slashing DMG" }
```

`normal: 8.107` 是**一整套普攻加起来**的值，拆不出 1 段、2 段、3 段；也没有天赋等级维度、没有每跳的缩放属性、没有物理/元素标记。竞品那张表我们现在**造不出来**。

武器同理：只有 `baseATK` 和一条副词条，没有被动、没有精炼。

## 3. 目标形态

保留六乘区作为「为什么」，新增伤害明细表作为「是什么」，两者联动：

```
┌─ 角色 · 等级 · 命座 · 天赋等级 ─┬─ 武器 · 精炼 · 被动层数 ─┬─ 敌人 ─┐
├─────────────────────────────────┴──────────────────────────┴────────┤
│ 左栏：六个乘区（可编辑）        │ 右栏：吸顶结果                      │
│  ① 基础 ② 增伤 ③ 暴击          │   期望伤害 + 公式链                 │
│  ④ 反应 ⑤ 防御 ⑥ 抗性          │   各乘区贡献                        │
├─────────────────────────────────┴─────────────────────────────────┤
│ 伤害明细表：每一跳 × (不暴击 / 暴击 / 期望)                         │
│   点任意一行 → 六个乘区切换到这一跳的数据                            │
└────────────────────────────────────────────────────────────────────┘
```

**联动是关键差异点**：竞品的表只给结果，我们点一行就能看到这一跳的六个乘区怎么构成的。

## 4. 数据工程（工作量的大头）

全部从 **genshin-db** 生成，脚本进 `scripts/`，产物进 `src/data/generated/`，**不手改**。现有 `scripts/fetch-weapon-icons.mjs` 是可参考的先例。

### 4.1 天赋（最优先）

目标结构：

```ts
interface TalentEntry {
  id: string;            // 'normal-1' | 'skill-jumpy' ...
  group: 'normal' | 'charged' | 'plunge' | 'skill' | 'burst';
  label: string;         // '1-Hit DMG'
  values: number[];      // 15 个等级的倍率
  scaling: ScalingStat;  // 这一跳吃攻击/生命/防御/精通
  element: ElementType;  // 物理还是元素 —— 修掉优菲娅那类错误
  hits?: number;         // ×3 / ×8 这种
}
```

要做的判断（脚本里写清规则，不要逐个手填）：

- **缩放属性按跳判定**，不再挂在角色上。这修掉「用 4 万血乘普攻倍率」那类错误。
- **物理/元素按跳判定**。普攻默认物理，法器和有元素附魔的除外。
- 非伤害条目（持续时间、冷却、能量）单独标记，不进伤害表。

### 4.2 武器

```ts
interface WeaponData {
  // 已有：id / name / type / rarity / baseATK / secondary
  passive?: {
    name: string;
    text: string;
    refinements: 1|2|3|4|5;
    // 用户可选的档位，而不是自动模拟
    stacks?: { label: string; buffs: Partial<BuffState>[] }[];
    buffs?: Partial<BuffState>[];   // 按精炼 5 档
  };
}
```

**关键设计：武器被动做成用户可选的层数/开关，不做自动模拟。**竞品就是这么做的，这既准确又省一半工作量。这是目前白板数字偏低的最大原因。

### 4.3 其余

- 圣遗物套装：`artifactSets.ts` 已有数据，补 2 件套效果并接进 UI，条件类做成开关
- 命座：每个命座一条效果，条件类同样做成开关
- 角色被动 A1/A4：同上
- 敌人：`resistances` 改成七元素 + 物理各自可填，并支持抗性/防御削减

## 6. 必须守住的既有约定

1. `addBuffs` 相加，不要 `Object.assign` 覆盖。
2. 基础暴击 5% / 50% 已在引擎内处理，UI 不要重复加。
3. 反应等级系数用 `REACTION_LEVEL_MULTIPLIER` 全表。
4. 扩散按被扩散元素算抗性（`swirlElement`）。
5. `useCountUp` 的兜底不能删（rAF 不触发时要落到终值）。
6. 重算 memo 化，单次输入不产生 >50ms 长任务。
7. 版式：内容宽 1040、两侧广告位、导航不吸顶、无滚动动画、H1 居中。
8. 判断控制台是否干净**必须重启 dev server**，HMR 会留过期报错。

## 7. 已知 bug（P0 修掉）

- **技能倍率输入框**：标签是 `Skill multiplier %`，`max=100`，但存的是原始倍率（班尼特显示 `5.41`，实为 541%）。实测把它设成 `1`，伤害变成 298 —— 说明按 ×1 处理。用户照游戏里写 541 会被 `max=100` 截断。要么标签去掉 `%` 并改成 `×`，要么输入按百分比再除以 100。
- **计算器区没有 H2**：改成单角色后标题被删了，文档大纲现在 H1 之后直接跳到「How Genshin damage is calculated」。对主关键词页是硬伤。

## 11. 角色自身状态（brief #5 新增）

角色的输出大多发生在某个技能状态里（胡桃开 E、雷神开 Q），没有状态开关时这些主 C 的数字整体偏低，普攻元素也算错。和队伍增益一样走**用户声明制**：开关由用户打开，我们不猜覆盖率。数值由 `scripts/generate-state-params.mjs` 从 genshin-db 生成到 `src/data/generated/stateParams.ts`，定义在 `src/data/selfStates.ts`。
