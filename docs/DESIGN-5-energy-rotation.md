## 1. 这个功能到底要回答什么问题

现在的工具回答"这一击打多少"。玩家真正想比较的是"一轮打下来总共多少"。
所以输出目标是一个数字：**平均 DPS = 一轮总伤害 ÷ 一轮时长**，
并附一轮的伤害构成（哪个技能贡献了多少）。

## 2. 三档方案，建议只做 M1

### M1 —— "充能循环"模型（推荐，唯一建议先做的）

一轮 = **两次元素爆发之间的一段稳定循环**，长度由能量平衡推出：

```
充能需求 = 爆发能量上限
每轮产能量 = Σ(队伍粒子供给估计) × 充能效率(ER)
轮时长 = max(技能CD下限, 打完全部动作需要的时间, 能量攒够所需时间)
轮内伤害 = Σ( 每个动作的单击伤害 × 次数 )
DPS = 轮内伤害 / 轮时长
```

用户输入只加两样：
1. **动作清单**：从现有 per-hit 表里勾选行 + 每行次数（行数据已经有了，
   UI 就是 DamagePanel 的表加个数量输入框）；
2. **爆发次数/轮**：默认 1。

关键取舍：**粒子来源不模拟实战，而是给一个"场上/场下产粒估计"滑条**
（每技能命中产 3/4/5 微粒这种数据 genshin-db 没有，硬编码会做错）。
宁可让用户自己声明产能量，也不替游戏瞎猜。

不做的事：时间轴模拟器、切人顺序、轴对齐、爆发卡肉。那些是 M2/M3 的
复杂度，收益对单人计算器不成比例。

## 3. 数据缺口（必须先说清楚）

- genshin-db v5.2.13 **没有** 每技能产粒数、爆发能量消耗的结构化字段
  （能量消耗散落在部分 talent 文本里）。M1 的产能量输入因此是
  **用户声明制**，默认值给 0（=只吃 ER 平A产粒都算不上的最保守状态）。
- 如果以后想要默认值，需要另起一个"手工整理 122 角色能量/产粒表"的
  工作包，那是数据活，不是模型活。
